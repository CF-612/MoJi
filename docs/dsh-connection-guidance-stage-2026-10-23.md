# DSH 连接卡片与插件部署引导（阶段记录）

## 实现

- 按作者最后确认的截图位置：在「工作台更多功能」面板顶部增加 DSH 专属「连接与存储」卡片，显示本机 / 个人云端及授权状态；移除右下角悬浮齿轮。没有把入口放入设置分类。
- 仅 DSH 原生入口注入连接能力，其他宿主不显示本机/云端切换卡。连接状态加载或失败时，在顶部提供同一张恢复卡及重试读取入口。
- 保留现有连接配置、OAuth、登出及数据位置语义：不部署服务、不迁移、不复制本地作品、不失败回退另一库。DSH 地址必须是 HTTPS 根地址，不是 `/mcp`。
- DSH 云端连接表单增加部署引导。Codex/MCP 内嵌界面的更多功能面板增加独立部署说明，说明实例由所用插件及宿主管理，不能在此直接切换；不宣称所有 Codex 插件必须使用某一种安装入口。
- 两端共享完整可视化工作台部署提示词；链接 `moji-release/docs/cloud-agent-deployment.md`，无固定版本和私有路径。要求先确认新建/更新、账号/资源/费用和真实变更授权；明确用户自行登录/隐藏密钥输入、禁止同名接管/盲重试、迁移另授权、不能将 CLI 或工具列表当作完整 GUI 验收。
- DSH 通过已有 `sendNativeReference` 当前会话通道发送；MCP 使用宿主 `message.text` capability + `app.sendMessage`，检查拒绝/断连。没有通道显示复制入口；发送失败保留手动复制文本。只有用户点击才发送，不创建 Agent 任务、不调用 sampling。

- `npm run typecheck`：通过。
- `npm run build:workbench --prefix integrations/chatgpt-workbench`：通过。
- CUA 已实际查看独立 mock fixture：DSH 更多面板卡片、云端表单引导、Codex 说明及引导、无发送能力时仅复制提示、状态错误仍能进入连接面板；360px iframe 侧栏无横向溢出（clientWidth=scrollWidth=309，纵向可滚动）。据实修复卡片样式被旧 sheet-actions 规则覆盖的问题与初始读取失败的状态文案。
