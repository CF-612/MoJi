# 交给 Agent 安装催更姬（Windows）

这份指南用于协助用户在 DSH Windows 桌面版安装催更姬。安装使用 DSH 原生插件管理和维护者提供的成品包，用户无需安装 Git、Node.js 或源码构建工具。

## 当前发布状态

截至 2026-10-06，插件源码版本为 **0.3.13**，已验证的桌面宿主为 **DSH 0.2.0-rc.2**。维护者已在 Windows 桌面版使用本地构建的 `.tgz` 包安装并运行插件；公开 GitHub Release 和 npm 包尚未发布，完整的无 Git 安装验收仍待完成。

免 Git 安装需要已经构建好的包。用户拿到维护者提供的 `.tgz` 文件后，可以通过 DSH 原生安装入口安装。公开下载入口发布后，在这里补充具体版本和直链；此前不要把包名或猜测出来的 Release 地址当成可用安装源。

源码仓库地址用于查看和开发项目。在 DSH 中直接安装 Git 仓库会调用 Git，不适用于本指南。

## 可以交给 Agent 的请求

> 请按催更姬仓库的 `docs/agent-installation.md` 帮我安装 Windows 桌面版插件。先确认我的 DSH 版本，再使用维护者提供的预构建安装包，通过 DSH 原生插件管理完成安装和启用。安装后检查催更姬入口和工作台是否正常。如果还没有可用安装包，明确告诉我缺少哪项发布资源；如果你不能操作原生安装入口，先准备好安装包及地址，再把剩余步骤交给我。

## 安装步骤

### 1. 确认当前桌面环境

- 以用户正在运行的 DSH 桌面程序、版本和数据目录为准。不要套用维护者电脑的安装路径。
- 当前兼容声明为 `0.2.0-rc.2`。其他版本应核对相应发布说明，不默认认定所有更新版本都兼容。
- 安装目标是当前桌面环境。使用 DSH 原生插件管理处理已有安装、更新与启用状态。

### 2. 取得真实可用的安装包

优先使用维护者提供的预构建 `.tgz` 文件，或从[官方 Releases 页面](https://github.com/mistnest/dsh-cuigengji-plugin/releases)选择已经发布的安装包。核对资产名称、插件版本和宿主兼容说明；如有校验文件，核对文件哈希。

安装源必须是以下形式之一：

- 已发布的 `.tgz` 下载直链。
- 已下载 `.tgz` 文件的 Windows 绝对路径，例如 `C:\Users\用户名\Downloads\dsh-cuigengji-0.3.13.tgz`。这是路径格式示例，实际以用户拿到的文件为准。
- 正式发布后提供的 npm 包名或指定版本。目前 `dsh-cuigengji` 尚未公开发布，不能直接用它安装。

GitHub 的源码 ZIP 不是插件安装包。没有成品包时，报告缺少发布资源，由维护者补齐；不要给普通用户临时安装 Git 或搭建源码构建环境。

### 3. 通过 DSH 原生插件管理安装

1. 打开当前 DSH 的插件页面和安装入口。
2. 填入已经核实的安装源，等待当前安装任务完成。
3. 在已安装插件中核对 `dsh-cuigengji` 的版本，并按原生界面提供的操作启用。
4. 如果宿主要求重新加载或重启，先让用户保存正在进行的工作，再按宿主提示完成。

能调用 DSH 原生插件安装接口或操作其界面的 Agent，可以继续完成这些步骤。只有文件或命令工具的 Agent 应先准备和核对安装包，再提供准确的安装源和上述界面步骤，由用户完成原生安装。

**桌面版的 `desktop` profile 由 Electron 应用专属管理。** 已验证版本的普通 `dsh` CLI 会拒绝操作这个 profile；不要通过创建同名 profile、直接运行 `pnpm add` 或手工改配置来绕过宿主管理。本仓库的源码安装脚本供开发者维护时使用，不属于普通用户的免 Git 安装流程。

### 4. 验证安装结果

安装任务成功只是第一项检查，还应确认：

- DSH 已安装列表显示预期版本，插件已启用。
- 左侧栏出现“催更姬”，点击后能打开小说工作台。
- 能创建一个专门的测试作品，打开正文、规划和设定页面。已有用户作品只做浏览，不在其正文上写入安装测试内容。
- 更新已有插件时，原来的工作数据位置和作品仍可访问。

以上过程无需调用模型。小说工具与模型实际协作的测试应作为后续单独验收，不把界面打开成功表述为所有模型行为都已验证。

## 安装失败时怎样报告

记录当前安装源、DSH 版本、插件版本、失败阶段和安装任务的具体错误。分享日志前移除凭据与私人内容。

- **提示找不到 Git，或失败命令是 `git ls-remote`**：检查是否误用了仓库地址，改用已核实的成品包安装源。
- **下载失败**：核对该资产确实已经发布、地址能访问，并查看当前安装任务的下载错误。
- **版本不兼容**：根据宿主与插件的兼容说明选择对应版本，保留宿主的检查结果。
- **装完没有入口或加载失败**：查看当前安装任务、启用状态和当前桌面环境的插件加载日志。

历史独立版催更姬的模型配置和 `debug/api-calls` 日志不属于当前安装任务。诊断时标明来源与时间范围；统计重复日志时按请求 ID 去重。

不要重复发起模型连通测试、重置 DSH 配置或覆盖小说工作数据来处理插件安装失败。

## 发布前的验收条件

维护者应在仅有 DSH、测试进程找不到 Git 的 Windows 环境中，按同一份指南完成安装、启用和工作台检查。分别验证远程 `.tgz`、本地 `.tgz`，以及公开发布后的 npm 安装与更新；安装不依赖用户侧的源码构建。

通过这些验收后再更新本文的发布状态和具体安装入口。开发者构建与打包流程见[开发、测试与发布](development.md)。
