# Moji 公开发布与多 Agent 适配规划

记录日期：2026-10-14。

本文保存已讨论的后续方向，不代表这些功能已经实现，也不是立即部署的指令。当前主要目标仍是打磨工作台：让正文、资料、规划、时间线与关系图真正联动，完善操作体验、性能和稳定性。公开部署与新宿主适配暂缓实施。

## 1. 发布目标与边界

- 公开源码，保留上游 MIT 许可与原作者署名。
- 不由项目作者承担公共云端托管费用，不建立必须依赖作者服务器的公共作品库。
- 用户可在本地使用，或把个人实例部署到自己的云账号。
- 同一位用户的 Codex、Gemini、DSH 等入口访问同一实例、同一份已保存作品数据。
- 各 Agent 的聊天历史和记忆仍由各自宿主管理，不自动合并。
- Agent 安装指南作为辅助；正常安装和部署不应要求用户具备 Agent、开发者工具或命令行经验。
- 本轮未授权联系上游作者、向上游提交 PR 或发布公共安装包；这些事项另行决定。

公开源码不等于提供免费的公共云服务，也不等于免除每位用户的云账号设置。免费额度可作为个人使用起点，不承诺永久免费、无限容量或永久可用。

## 3. 面向用户的两种使用方式

### 3.1 本地版

- 安装后可使用，不要求注册工作台账号。
- 首先服务于 DSH 等能访问本地插件的宿主。
- 作品存放在独立数据目录，提供导出、恢复和可验证的升级迁移。
- 本地插件不默认把作品暴露到公网。
- 本地服务不等于 Gemini 等云端客户端可直接访问；公共远程 MCP 需要可访问的 HTTPS 服务。

### 3.2 个人云端版

- 每位用户把应用部署到自己的云账号，获得自己的网页与 MCP 地址。
- 首版以单个作者、多个设备及 Agent 为目标，不要求建设公共统一账号平台。
- 目标流程：注册云账号与代码托管账号 → 点击部署 → 首次设置作者账号 → 接入所选 Agent。
- 可先提供 Cloudflare 部署模板；其他服务器部署作为后续扩展。
- 初始化向导生成配置、执行数据库初始化并检查部署结果，避免用户手工改多个文件。
- 免费额度、用量、备份和升级说明清晰可见；收费升级由用户自行决定。

第一版不同时建设网盘同步、离线双向合并与多个云后端。网盘可用于交换或备份文件，但不能直接替代供远程 Agent 执行事务的在线服务。

## 4. 共用核心与各端适配

采用共用业务核心、共用前端、各宿主适配层的结构。

共用核心负责数据模型、校验、查询、写入、版本冲突、幂等请求、历史、导入恢复，以及时间线和关系阶段投影。云端是所选实例的权威数据源。各端不重复实现这些规则。

共用前端负责正文、卡片、规划、时间线、关系图、仪表盘、主题及移动布局。宿主只负责承载界面、尺寸、登录与聊天联动。

| 更新类型 | 共用修改 | 客户端可能需要的处理 |
| --- | --- | --- |
| 新字段或新业务操作 | 核心、迁移和接口 | 旧客户端识别能力与版本；保留未知字段 |
| 新 AI 读写能力 | 动作目录、参数规则、权限和说明 | 刷新能力目录；必要时刷新宿主工具信息 |
| 新可视化板块 | 共用前端 | 网页更新；打包前端的插件重新构建、安装 |
| 新聊天引用或宿主快捷入口 | 对应适配层 | 只更新对应宿主 |

现有通用查询／修改工具采用动作名称与参数，可承载多数新增操作，但不保证所有宿主无需刷新。不能以“顶层工具名没变”为由省略参数说明、版本检查和能力查询。

避免长期维护两套界面源码：将当前适配前端与原宿主入口整理到可共用的模块，通过构建入口区分宿主。整理前建立稳定基线，不在文档阶段进行源码迁移。

## 5. Gemini 与独立网页

Gemini 继续通过 MCP 查询和修改作品。可视化优先通过独立网页提供，不依赖 Gemini 显示 MCP Apps 界面。

独立网页需要：

1. 普通网页入口，复用现有工作台组件。
2. 作者登录、退出和会话过期处理。
3. 携带有效身份的读写入口，复用核心校验与并发控制。
4. 作品深链接；链接携带作品定位信息，不携带访问令牌或密码。
5. 打开工具返回可点击的网页链接与简短文字结果。
6. 跨端修改后的轻量刷新；不覆盖未保存草稿，不制造频繁闪烁提示。
7. 手机、软键盘、网络中断与恢复验收。

现有本地预览接口不能不加认证就复制到公网。“加一个网页路由”也不代表完整登录与保存已实现。

Canvas 可用于临时展示、设计探索或只读快照，不作为主要编辑入口；生成页面不能未经验证就获得直接写入能力。MCP 文本输出可改善索引和摘录，但继续按需返回，不默认加载整本小说。

## 6. DSH 云端原生插件

建议保留原生侧栏体验，通过 DSH 连接适配层访问同一云端实例。

需要改造的边界：

- **界面**：DSH 原生侧栏承载共用前端，不要求宿主实现 MCP Apps 渲染器。
- **登录**：补齐浏览器授权、凭据安全保存、续期、撤销和过期提示；不把长期令牌写进公开配置或代码。
- **工具**：DSH 的查询与修改转到云端模型接口，补齐结构与导入能力；不能把模型操作伪装成人工界面操作来绕过权限。
- **会话**：为每条 DSH 对话保存独立作品／章节绑定；与 Codex、Gemini 的面板绑定隔离，不能共用一个全局“当前作品”。
- **写作要求**：按当前作品从云端读取启用的要求，不再从旧本地库注入。
- **聊天引用**：恢复“围绕此内容讨论”，保留实体 ID、读取版本和草稿标识。
- **存储**：云端模式不创建第二份自动写入的本地作品库。旧本地资料通过预览导入，原始文件保留。
- **宿主兼容**：按实际安装的 DSH 版本验证侧栏、工具注册和生命周期，不只依赖原版声明的宿主版本。

可使用独立入口或明确的模式设置保留旧本地版，不能静默把原插件切到云端。离线时提示未保存并保留草稿，不回落到另一份库假装保存成功。

验证顺序：工具只读 → 原生侧栏只读 → 虚构资料写入与跨端核对 → 会话绑定及写作要求 → 聊天引用 → 重启、登录续期和断网冲突。

## 7. 通用登录、部署与账号边界

当前个人部署使用外部 Auth0 和固定作者身份。公开模板不得包含这些个人配置。

首版个人实例需要安全的首次初始化：设置实例所有者后关闭无人认领入口，重启不重新开放初始化，不能仅靠前端隐藏注册按钮。

通用版不应强制用户重复申请外部认证租户、手工寻找客户端 ID、反复配置回调。候选方向是内置作者登录与标准 MCP 授权，外部身份服务可选。此方案尚未选型或实施，必须单独设计并验证 OAuth 客户端注册、精确回调校验、授权范围和会话生命周期；不能用永久共享密钥草率替代所有宿主的登录流程。

若以后支持家庭、团队或公共实例，再增加多用户注册、邀请与作品授权。服务端需要逐项隔离作品、引用、历史、备份、搜索、请求记录与缓存。用户 ID 不由客户端随意指定，知道作品 ID 不代表具有访问权。

补齐用户自助导出、恢复、删除数据、撤销客户端授权，以及数据流向说明。分别说明作品存储位置和 Agent 请求所发送的数据，不能把“自己托管”表述为“内容永不离开服务器”。

## 8. 费用、容量和发布纪律

- 项目作者维护源码与流程，用户承担其选择的托管服务费用。
- 用实测评估 CPU、存储、数据库读写和备份增长；不能只拿免费请求次数判断成本。
- 容量不足时明确拒绝并保留草稿，不默认启用付费服务或自动升级套餐。
- 一键部署模板与实例命名通用化，初始化资源、配置和迁移可重复执行。
- 提供升级检查和迁移说明，保留代码回滚与数据恢复的区别。
- 旧客户端不得覆盖新字段；不兼容时限制操作并说明如何升级。
- 公共源码只含源码、依赖锁文件、配置模板、文档与虚构样例。发布前扫描凭据、个人配置和作品数据。
- 本地包、公共版本与私有云端发布分别管理。不得将代码提交自动变成覆盖线上或发布安装包的授权。

## 9. 实施优先级

### 当前：工作台打磨

继续完善现有写作流程、时间线与关系联动、AI 整理建议、检索定位、性能、数据安全及移动操作。上述新宿主和公开化工作不抢占当前主线。

### 后续第一阶段：共用边界与网页

整理共用前端与连接接口，完成独立网页、登录及受保护读写。使用虚构资料验收，再接现有私有库。

### 后续第二阶段：DSH 适配

按第 6 节顺序验证工具和侧栏；保证 DSH、Codex、Gemini 同一数据源、不同对话绑定。

### 后续第三阶段：个人实例公开发布

完成通用初始化、身份认证、部署按钮／向导、打包、升级、容量检查及公开文档。让不了解项目的新用户从干净环境走通一次安装与恢复流程，再决定发布。

多用户协作、第三方托管伙伴、更多云后端、网盘同步和离线双向合并不属于首版必做项。

## 10. 最低验收条件

- 无项目作者个人凭据也能部署新实例；未登录不可读写作品。
- 所有入口读到同一虚构作品和修订；跨端修改能刷新，但不覆盖草稿。
- 新板块的界面与 AI 操作遵守同一校验及权限，旧客户端不破坏新字段。
- 不同宿主、不同对话的绑定互不串用。
- 过期授权、断网、重复提交、并行修改和撤销连接给出真实结果。
- 导出包含新增字段与历史；恢复有预览，并实际验证可重新读取。
- 升级可回退代码且保留最新数据；旧本地库不会被静默覆盖。
- 发布源码和安装包不含真实作品、日志、备份、个人配置与凭据。

## 11. 项目名称、图标与来源

公开版本建议采用独立名称和原创图标：项目已从单宿主小说插件扩展为具有结构化资料、动态关系、多轴时间线与跨 Agent 云端操作的工作台。独立品牌用于明确维护者与产品方向，不抹去来源，也不将上游停止更新视为项目归属转移。

在关于页与 README 保留基于原版催更姬的说明、上游链接、原作者署名及 MIT 许可。原图标、插画等资产逐项确认使用依据，不从源码许可推断所有第三方素材均可重新发布。新图标优先制作原创资产。

先决定对外名称、定位和视觉标识，之后才改包名、插件标识与地址。已有数据 ID、引用、偏好键和客户端回调不能通过全局字符串替换来改名，需保持兼容或提供明确迁移。

## 12. 可选模块与社区扩展

目标是允许用户选择极简或完整工作台，同时让贡献者增加功能而不改遍所有主页面。当前页面入口有集中硬编码，扩展操作也汇集在共用分发逻辑中，因此需要逐步整理接口，但不推倒重写。

### 核心与模块

- 稳定核心保留作品／章节／资料实体、ID 与引用、版本和事务、权限、历史、导入恢复。
- 时间线、关系阶段视图、伏笔辅助、仪表盘等作为可选模块；视图复用核心记录，不各建一份人物或事件库。
- 第一阶段先支持随应用发布的内置模块开关、导航配置与按需加载；不立即提供运行任意远程代码的插件市场。
- 后续建立明确的模块描述：稳定 ID、版本、核心兼容范围、依赖、导航／面板入口、查询与写入操作、数据迁移和所需权限。
- 前端显示开关、实际功能停用、插件卸载分别处理。隐藏页面不代表撤销 AI 写入权限。
- 停用后保留记录、历史、导出数据和引用；重新启用可恢复原内容。卸载及清理数据是单独且明确的操作。
- 数据读取和备份层保留未识别扩展数据；不能在模块未加载时静默丢弃字段或声称已完整校验未知格式。

### 个性化与联动

提供极简、标准与完整配置作为可编辑起点，而不是三套不同软件。正文保持首位；作者可以隐藏仪表盘、时间线等入口。设备布局偏好与作品所启用的业务功能分开保存，例如手机隐藏面板不应关闭电脑上仍在使用的事件操作。

模块通过稳定实体引用和受控操作协作。正文跳转时间线、关系图随事件变化、伏笔显示在章节节点等交互通过模块能力声明提供；模块关闭时隐藏对应入口或给出可理解的提示，不留死链接。依赖必须明确，避免出现页面开了但所需记录操作被禁用的半可用状态。

### 社区建设

先提供贡献指南、模块模板、少量真实模块示例和虚构资料验收案例。社区模块首阶段通过源码贡献和构建安装验证，成熟后再考虑独立安装、权限提示、兼容性检查与沙箱执行。

新增写入操作仍经核心身份、归属、版本和幂等检查；模块不能直接绕过事务修改数据库。对 Agent 返回的是当前实际可用能力，与页面功能开关保持定义一致。

以上作为公开版架构方向保留。当前优先工作台打磨；可在后续功能修改中渐进整理集中分发与导航，不立即实施大规模插件系统重构或更换品牌。

## 13. 参考资料

以下能力与限制可能随产品变化，实施时重新核对。用户实测优先记录为具体账号／客户端结果，不外推为全平台保证。

- [Cloudflare Workers 费用](https://developers.cloudflare.com/workers/platform/pricing/)：免费与付费额度，实施时同时核对所用数据库和其他服务限制。
