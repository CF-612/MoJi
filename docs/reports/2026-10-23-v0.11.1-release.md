# Moji 0.11.1 修复与发行记录

## 范围与当前状态

本轮针对用户反馈的跨行连线不自然、时间线窄屏/手机缺少单项与批量删除入口进行修复。版本为 0.11.1，0.11.0 的标签与发行附件保持不变。

当前状态：圆弧连线候选已通过代码与页面检查，候选构建及封包验证完成，用户已确认外观；尚未发布 0.11.1。

## 修改内容

- 规划卡片共享连线几何：采用连续圆弧回转处理特殊跨行连接，避免机械或尖锐的拐弯；普通可直连路径保持自然走向。
- 叙述与故事时间线：补充窄屏单项删除与批量删除入口，确认窗口只处理选中项；保留编辑草稿保护。
- 故事时间线“更多”补齐撤销入口，与删除提示一致；删除后可以恢复。
- README 规划图示同步实际效果；删除作者指定的多余宣传段落。
- 发行版本元数据统一为 0.11.1；历史报告不改写。

## 包体与发布验收

已重新构建 DSH tgz、Windows 独立版 ZIP、个人插件包生成器 ZIP，以及 SHA256SUMS。包内版本、README、编译客户端与当前源码一致；私有路径排除及包文件清单审计通过。

DSH 提取包在 Linux Node 24.19.0 上通过空数据初始化与公开合成 0.3.13 旧数据升级（2 本作品、3 章、5 个历史版本、1 个回收章节）。Windows 包内服务在 Linux 系统 Node 上通过页面读取、跨站请求隔离、正文/梗概保存及重启恢复。个人插件生成器用合成 HTTPS 地址离线验证输出三个指定文件、版本和 MCP 地址，并在公共 ZIP 封装前移除合成个人包。

尚待：推送对应源码并创建正式 Release；匿名下载公开附件核对字节与哈希后，才更新默认分支更新清单。

Windows 包内服务及 DSH 编译运行时在 Linux 的测试不等于 Windows / DSH 原生界面验收。生成器公共 ZIP 不是直接上传宿主的个人插件包；必须由用户提供自己的 HTTPS 实例地址生成。

本轮不在 dot 环境部署用户唯一的个人云端，不创建新实例或数据库。Git 推送、GitHub Release 发布与私人云端部署是三个不同状态。
