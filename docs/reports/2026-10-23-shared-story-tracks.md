# 故事时间线：共享轨道、自由上下摆放与日期编辑修复

## 本轮要求与实际行为

- 叙述时间线由作者建立的轨道现在可直接用于故事时间线；两处读取同一名称、颜色定义，重命名不改卡片位置。
- 故事时间线不再把「轴上／轴下」作为固定的命名轨道或主支线分类。画布上下只是位置；同一轨道的事件可以放在任意一侧。轨道筛选独立于上下摆放。
- 故事时间线中新建的轨道进入共享目录。旧的独立故事轨道保留原身份和数据，不按名称合并、不自动迁移。旧轨道仍可修改；已有事件占用时不能删除。
- 拖动只改故事日期、侧面与行位置，保留选中的轨道；不会改变叙述章节顺序、画布或大纲关系。

## 兼容性与接口

旧版 `time.story.trackId` 仍指向 `storyAxis.tracks`。新增可选 `trackSource: 'shared'` 才指向 `state.tracks`；两边出现相同 ID 不会串轨。UI 编码键不写入正文数据，长 ID 和带冒号 ID 不受前缀污染。

新增可选 `time.story.side: 'above' | 'below'` 表示单个事件的摆放位置；旧数据缺少此字段时继续采用原故事轨道的 side。复制／导入根据来源选择相应 ID 映射，保留 source 与 side；备份、恢复、撤销、重做及局部导出保持这些字段。

`storyAxis.place` 接收上述可选 source/side；未知值拒绝。共享目录目前没有 `track.delete` 操作，不新增静默删除。旧故事轨道删除只检查真实旧轨道引用，不能把同 ID 的共享引用误判为占用。

## 同时发现并修复的真实问题

上一轮卡片编辑面板已有故事日期字段，但保存走普通 `card.update`，后端禁止改故事时间，导致日期与正文一起修改时被拒绝。之前实际浏览器验证的是状态修改，不能据此声称日期修改也已验证。

现在编辑面板明确发送 `storyPlacement: true`，在同一次 card.update/CAS 中校验和保存日期及内容。无此标志仍不能移动故事日期；旧 `placement.mode: 'story'` 路径仍禁止用于配置后的独立时间线。日期非法或版本冲突时整次操作拒绝，不部分保存标题／正文。旧未映射时间保留 legacyStoryTime 来源。

## 实际拖动验收后追加修复

主任务实际浏览器验证发现：只上下拖动卡片也改变日期。旧逻辑从视觉卡片中心逆算日期，中心与 CSS 实际时间锚点偏差产生固定漂移。改为以开始拖动时的原日期为基准，仅叠加鼠标水平位移与横向滚动位移；纯垂直拖动直接保留精确原日期，不做有损投影往返。拖动仍保留原时长与轨道身份。
