# 两种时间线：自定义轨道排列与整轨摆放

## 用户确认的范围

在已发布 0cf0361 基础上补齐轨道管理：两个时间视图均可调整自定义轨道上下顺序；故事轨道可整组移至时间轴上方／下方。保留逐卡自由摆放，不把上方／下方定义为主线／支线。

## 已实现入口与行为

### 叙述时间线

点击轨道名称打开「轨道设置」，继续编辑共享名称和颜色，增加「叙述视图排列」上移／下移。排列实际改变轨道分组的纵向位置，不只是排序下拉菜单。故事轨道排列独立，不随之改变。

### 故事时间线

右上角更多内点击对应轨道设置，或点击画布上轻量轨道分组标签：

- 名称和颜色编辑仍共享。
- 「故事视图排列」上移／下移：实际移动卡片分组顺序；同一轨道在两侧都有卡时，两侧均遵循同一故事轨道顺序。
- 「整条轨道摆放」全部放到轴上／轴下：先显示匹配卡片数，再确认；不修改日期、时长、叙述安排、章节或大纲。
- 该明确操作也设置此轨道以后新卡片的默认侧；空轨道同样可以设置。旧的单卡显式位置优先，之后仍能把任意卡片单独移到另一侧。
- 名称／颜色尚未保存时禁用排列和整轨动作，避免在执行另一个动作时悄悄丢弃草稿。
- 故事轨道只有细小标签与间距，没有重新引入强烈上下背景区块或固定主支语义。

## 数据与兼容性

共享名称/颜色保持原目录；新布局为可选的每视图字段：叙述 `narrationTrackOrder`，故事 `storyAxis.trackOrder`、`storyAxis.trackSides`。旧数据无字段时维持原顺序与旧侧面回退，不自动迁移。

操作为 `track.reorder { mode, order: [{trackId,trackSource?}] }` 与 `storyAxis.track.side { trackId,trackSource?,side }`。共同使用 workspace CAS；整轨动作只提升实际改动卡片的 revision，防止旧草稿覆盖。旧故事轨道和共享轨道同 ID 通过 source 区分。

复制、导入、恢复、撤销、重做、空轨默认侧、旧轨删除后的顺序清理由 domain 专项验证。本轮不增加删除共享轨道功能。

## 组合窄视口检查发现的真实问题

主任务在 390×480 的缩短视口并同时开启宿主聊天栏模拟时，发现故事轨道弹窗滚到底部后保存按钮仍部分被遮挡（普通 390×820 场景不复现）。原因是全局 preview-polish 的 `max-height!important` 覆盖了故事面板扣除顶部、底部安全区的高度；通用移动端 margin 又消耗空间。
