# DSH 更新后：让本机助手修正 MoJi 的兼容版本声明

这份指南用于：**DSH 更新了，MoJi 功能没有实际接口变化，只是插件允许的宿主版本列表尚未包含新版**。让用户自己的 DSH 助手在本机做最小修正即可；若是真正的大更新／接口不兼容，由 MoJi 维护方适配，不要求用户自行改业务代码。

## 先说清楚改哪个版本号

要修改的是**正在加载的 `dsh-moji/package.json` 中 `engines.dsh` 的兼容范围**，只精确追加本机实际 DSH 版本。例如原值为：

```json
"dsh": "0.2.0-rc.2 || 0.2.1-rc.2 || 0.2.1-rc.3"
```

本机确实运行 `0.2.1-rc.5` 时，追加为：

```json
"dsh": "0.2.0-rc.2 || 0.2.1-rc.2 || 0.2.1-rc.3 || 0.2.1-rc.5"
```

不是修改宿主自己的版本，不是把 MoJi 的 `version` 伪装成新版，也不是将范围改成 `*`／`>=0`、放行所有未来版本。这里的 rc5 是已验证示例，不是永远通用的最新版本。

## 直接复制给自己的 DSH 助手

> 请检查本机 DSH 更新后 MoJi 的加载情况。如果只是 dsh-moji 的 engines.dsh 没列入当前宿主版本，请在本机完成兼容声明的小修复，不用让我手改文件：
>
> 1. 从实际运行的 DSH 获取精确版本（含 rc/alpha 后缀）、当前 profile 和插件解析路径。不要拿另一份终端 CLI 的版本代替桌面宿主版本；不要猜数据目录或全局 node_modules。
> 2. 查看第一条加载错误及 dsh-moji 的 package.json。只有明确因 engines.dsh 版本范围不满足而拒载、且没有已知 API／服务／格式不兼容证据时，才尝试此修复。版本号相近本身不是兼容证明；有实际不兼容或无法核实时停止，报告维护方。
> 3. 保存我的工作，记录当前包的实际路径、插件版本、原兼容范围、profile、dataRoot；备份该 package.json，确认作品已有完整备份。完整退出宿主后修改，或按宿主支持的安全停用／重新加载流程操作，禁止在使用中覆盖包。若你的操作能力依附于这个 DSH、退出后无法执行，请先准备好后续操作或让我退出后运行，不要声称已经操作。
> 4. 只在确认的 dsh-moji/package.json 中，把当前 DSH 的精确版本用“ || ”追加到 engines.dsh；已有则不重复。保留所有旧允许值、其他字段、插件 version、宿主文件、锁文件、业务代码、作品和配置不变。不得使用 allow-version、改 compatibility.json 或宽泛通配符代替这个修改。
> 5. 重新加载或完整重启正确的 DSH 实例。核实实际加载的就是刚才修改的包：插件启用、MoJi 维护状态 ready、6 个 MoJi 工具和6 个 Skills 能注册、原作品路径及列表一致。只在测试作品／副本中做最小读取、保存、重开；不要拿我的正式正文试写。
> 6. 若仍无法加载，出现缺失服务／导出／方法、工具协议或参数错误、迁移／数据错误，立即停止进一步适配，恢复备份的 package.json 并重新加载；保留新写内容，不回滚覆盖作品。向我和维护方报告原始错误、两个实际版本、修改文件与回滚结果。不要继续改接口或业务代码。
> 7. 给我简短结果：修改了哪个包、原范围→新范围、实际宿主版本、重载与验证是否通过。未完成的项目明确标记，不把“改完版本号”当作“已兼容”。

## 助手怎样找到真实文件

1. 先在**当前运行宿主**的插件管理／诊断中找到 `dsh-moji`，核对当前 profile、已加载版本、插件包位置。不要按下载目录或项目源码位置修改。
2. 若管理界面不显示位置，结合当前 profile 清单和宿主实际包解析结果定位；DSH 使用安装作用域与 profile 作用域解析，包可能在包管理器的实际目录中，不能固定假定为 `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-moji`。
3. 读取候选 `package.json`，必须确认 `name` 为 `dsh-moji`、`version` 与当前插件一致，并确认它是**实际解析到的那一份**。无法确认就停止；不要扫描后批量改所有同名包。
4. 如果解析文件被多个 profile／项目共享，或者它是只读／受管理的签名资源，先停止并说明影响，不能为了写入而提权、放宽权限或修改其他 profile。由维护方提供适配包更合适。
5. 备份放在插件目录之外、作品目录之外，以原路径和时间记录；恢复时校验备份身份。重装／升级 MoJi 可能覆盖本地声明修复，这是正常的；应重新检查实际版本，不永久关闭检查。

## 哪些错误交给维护方

| 情况 | 本机助手应做什么 |
| --- | --- |
| 只有 `engines.dsh` 不含当前精确版本 | 按上面流程备份、尝试单点修改、重新加载并验证；验证失败恢复。 |
| `@deepseek-ai/dsh-*` 内置组件版本混杂 | 检查是否启动旧实例／宿主安装损坏；不通过修改 MoJi 范围掩盖，交宿主维护／安装修复。 |
| 缺失服务、API／导出改变、工具协议错误 | 恢复兼容声明，保留脱敏日志，由 MoJi 维护方适配。 |
| 迁移失败、作品变空、存储格式不匹配 | 立即停止写入、保留现场；不建空库、不手改数据版本、不覆盖作品。 |
| 包路径无法确认、文件只读、共享目录影响不明 | 不修改，提供实际定位信息给维护方。 |

大小更新不能单看版本号判断：即使只是 rc 后缀变化，也可能需要维护方处理；反过来，单纯未列入版本的拒载不必让用户等待完整业务改版。

## 回报模板

```text
实际 DSH 版本／桌面或 CLI：
MoJi 版本／当前 profile：
确认的实际 package.json 路径（公开时隐去用户名）：
第一条拒载错误（脱敏）：
原 engines.dsh → 新 engines.dsh：
备份路径、重载结果：
工具／Skills、maintenance、数据路径、测试副本验证结果：
是否回滚，尚未通过的检查：
```

不要公开密钥、Cookie、完整 profile、私人正文或作品备份。本地声明修复只影响这份安装，不等于官方 MoJi 已发布适配；真正接口变化由维护方修复并发包。

官方依据：[DSH 发布记录](https://github.com/deepseek-ai/deepseek-harness/releases)。本次 [rc5 实测说明](dsh-rc5-compatibility.md)；维护方反馈：[MoJi Issues](https://github.com/CF-612/MoJi/issues)。
