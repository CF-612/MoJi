# 从催更姬 0.5.0 迁入墨叽

**使用完整作品数据包，不要让两个应用共用同一个作品库目录，也不要把 `storageVersion: 5` 手改成 `4`。** 原库和原始导出文件始终保留。

## 三种版本不是一回事

| 项目 | 催更姬 0.5.0 | 墨叽 0.11.4 |
| --- | --- | --- |
| 应用版本 | 0.5.0 | 0.11.4 |
| 本地库目录布局 `library.json.storageVersion` | 5 | 4（可升级读取 2、3） |
| 完整作品包 | `cuigengji-package`，`version: 1` | 同一包封装，仍须校验具体内容 |

v5 将规划节点和框/便签正文拆成独立文件，页面改为引用清单；v4 不能按旧路径直接读取。拒绝打开新布局不等于作品包不能导入，也不表示原库损坏。仅改版本号、删掉规划或装饰后“降级”都不是迁移方案。

## 推荐操作：独立库恢复完整作品

1. 在催更姬 0.5.0 保存所有编辑，确认正文自动保存完成。若要额外复制物理库，先退出正在写入它的宿主，保留独立副本。
2. 在原应用「导入 / 导出」选择 **作品**，选中整本作品，导出数据包。不是正文 TXT/Markdown，也不是仅复制 `library.json`。不要手动修改包内哈希或版本字段。
3. 打开使用**独立数据目录**的墨叽，或自己的独立云端工作库。不要配置成催更姬原目录。首次建议先迁移一本并核对，不急着停用原应用。
4. 选择文件，使用 **恢复备份 · 保留原作品和版本**。核对书名、章节、人物世界、规划数量、警告和冲突。恢复保留 ID；完整作品包不含原宿主聊天、API 配置和登录信息。
5. 确认导入后，重新打开作品，核对正文与梗概、历史与回收站、设定和关系、画布/节点/连线/框/便签、分组、写作预设。尤其要试读一条旧资料历史；不要只看“导入成功”。
   - 资料正文历史位于 **资料详情 → 故事历程 → 资料内容历史**，不是“设定字段”的字段历史。
   - 上游规划尚未自动转换为墨叽统一剧情卡。进入规划后点击 **查看导入的旧规划**，可按原画布只读核对情节正文、连线、原位置、分组、框与便签。下方新剧情工作区为空不表示旧规划被删除。整本导出保留两者；“规划”局部导出仅选择统一剧情页，不代替完整作品备份。
6. 从墨叽再次导出完整作品包，另存为迁移后备份。确认满意前保留原库与上游导出文件，不覆盖、不删除。

若提示格式、哈希、引用或历史无效，应停止导入并保留原文件，不删除报错字段“试到成功”。单个 JSON 导入受 64 MB 内容校验上限约束（压缩传输也限制解压后大小）；超出时优先按作品分别导出，云端还受实例容量限制。

## 恢复、替换、复用的区别

- **默认恢复**：补入缺失作品。相同 ID 且内容相同会跳过；同 ID 不同内容拒绝覆盖。导入前自动快照，预览后目标变化须重新预览。
- **Workbench 显式替换恢复**：只有作者确实要回退现有作品时，勾选“替换备份内的同 ID 作品”。它提高对象版本号，保留未选作品、当前绑定与操作记录，不是数据库时间旅行。DSH 原生界面不一定提供该选项。
- **复用内容**：新 ID、内部引用重映射，设定需要重新确认，写作预设停用。它不是保真恢复：作品级封面/分类/状态、旧时间线布局、剧情撤销历史等不等同于源作品。完整迁移优先使用恢复到独立库。

## 已验证的范围与明确限制

仓库中的两份**纯合成** fixture 由固定上游提交 `e9b78d065c0a681c6c516d7bb6f66ecb48108203` 的真实 `Store.dispatch` 和 `TransferService.export` 生成，源物理库确认为 v5；不是把墨叽包改名模拟。

回归覆盖整本恢复、磁盘重启、再导出，以及本地 → 隔离 D1 → 本地的包传递：章节多版本/回收站、设定多版本/关系、嵌套分组、规划节点/连线/框/便签、预设。另一 fixture 覆盖多个设定画布（含空页）和跨页关系。MoJi 自身的正文梗概、内嵌封面头像、剧情卡/分组/历史、时间线布局另有完整恢复测试。

已有导入器会给上游关系补齐墨叽的四项显示默认值（`category: other`、`timing: base`、`baseActive: true`、`style: solid`）；因此不是整个 JSON 字节完全相同。测试比较原字段及明确的默认化结果。

**本迁移补丁的修复**：上游资料历史使用扁平快照，墨叽历史界面原先期待 `value`。现在在历史查看、恢复与复用时兼容两种形式，保留导入文件中的原历史记录；复用时同时重映射嵌套分组父引用。未安装包含此补丁的构建时，不应把 0.11.4 的“成功存入”理解为所有历史操作都兼容。

**仍不承诺功能完全等价：**

- 墨叽设定界面是合并视图，不提供上游独立设定画布和嵌套目录的全部交互。完整恢复保留这些元数据；含多个设定画布的资料暂不支持复用合并，会在预览阻止而非丢掉画布引用。
- 删除含子组或分组批注的导入分组、跨设定画布移动资料分组、向上游独立资料画布新增/续建设定会拒绝，避免破坏保留的结构。其他上游特有组织/协作能力不因字段保留而自动可用；需继续使用原应用时保留原库。
- 没有验证墨叽增强字段回传上游后的完整编辑语义，不能宣称双向无损兼容所有功能。
- 作品包不含 DSH 聊天、外部附件、API 密钥、浏览器未保存草稿和界面偏好；内嵌作品封面/头像与外部附件不同。
- 本地/云端作品包可用同一导入边界；整库的独立日志附件、旧云端审计时间轴、部署配置不等于作品级恢复范围。
- 验证使用隔离合成数据，不接触真实小说或生产 D1；不替代用户数据的独立备份和迁移后核对。
