# 安装与开始使用

## 手机 GPT、电脑 Codex 与 DSH 怎么选

从 [GitHub 项目仓库](https://github.com/CF-612/MoJi) 获取源码及已核实的发布资产；不等待 OpenAI 官方插件目录上架。云端插件由使用者自部署、配置自己的实例并完成授权。

- **电脑 Chat／Work／Codex 与手机 GPT 的统一插件**：先部署个人云端、注册并授权自己的 ChatGPT 云端应用，再用实例网址和该应用 ID 生成统一包。只有网址的电脑 MCP 直连包不能当成跨端包。上传、授权和各端实际打开需要分别验证，能力受账号、工作区及宿主支持限制。
- **DSH**：可使用本机作品，也可连接已有个人云端；“本地 / 云端”的本机／云端切换面板仅供 DSH。两份库不自动同步，切换不会自动上传作品。
- **Windows 独立版／本机浏览器**：属于独立本地入口，不是 Codex 插件的本地模式。
**需要手机／多端共用作品时，从[个人云端部署与跨端连接](cloud-agent-deployment.md)开始。** 其中包含账号、源码选择、安装依赖、登录、新建／更新、密钥、健康检查、OAuth、备份试导入和保存重开步骤。DSH 填 HTTPS 根地址，MCP 填根地址加 `/mcp`；工作台密钥只在隐藏输入或本人核对过的授权页填写，不发进聊天。

已有[可复制部署提示词](cloud-agent-deployment.md#让当前-agent-帮忙已有部署提示词)，DSH 也可从「本地 / 云端 → 个人云端」交给当前 Agent。

个人云端部署好后，运行 `npm run package:plugin -- "https://你的实例.workers.dev" --app-id "plugin_asdk_app_本人应用ID"` 关联本人已注册的云端应用，生成统一插件 ZIP；无须手填图标、名称、简介或 OAuth 客户端密钥。上传权限、授权与完整 GUI 验收见[插件打包指南](plugin-package.md)。

**手机用户：**先在电脑网页完成云端应用注册、授权和统一包上传，手机登录同一账号／工作区后刷新插件列表，用 `@` 查找墨叽。已有连接和插件直接复用、更新，不需要再部署或新建一套。详见[参数填写示例](plugin-package.md#两个参数具体怎么填)和[手机接入步骤与排查](plugin-package.md#想在手机-chatgpt-应用里使用)。应用 ID 从云端应用详情 URL 复制，不是工作台密钥，也不是 ZIP 插件的 `Plugin_…` ID。

## 先试用工作台

本仓库需要 Node.js 24 或更新版本。克隆后运行 `npm ci`，然后运行 `npm run preview:workbench`，打开返回的地址。预览使用独立临时目录，不读取你的日常作品，也不提供真实模型对话。

也可以用自己的单本作品备份创建试用副本：

```powershell
npm run preview:workbench -- "C:\你的备份目录\作品.cuigengji.json"
```

修改只写入临时副本。要保留内容，请在预览工作台中导出。

## 安装到 DSH Windows 桌面版

当前 Moji 版本与 DSH 兼容范围以 `package.json` 为准；兼容声明不等于此版本已完成真实宿主验收。旧上游 0.4.0 Release 不是当前 Moji 安装源。

优先从[项目 Releases](https://github.com/CF-612/MoJi/releases)选择已核实的 `dsh-moji-<版本>.tgz`，通过 DSH 原生插件页安装；普通用户不必先编译源码。需要当前候选版新功能时，应核对候选版发布说明并选择对应包，不把较早的稳定版当作当前候选版。没有合适成品包时，再按 Agent 安装指南从源码构建。详细步骤见 [Agent 安装指南](agent-installation.md)；没有实际发布资产时不要使用猜测的下载链接。升级前备份并核对数据根，见[更新说明](upgrade.md)。

### 开发者本地安装

下面的源码构建流程仅供开发维护使用。

1. 安装并启动过 DSH 桌面版，让它创建 `desktop` profile。
2. 克隆本仓库，进入项目目录，执行 `npm ci`。
3. 从 DSH 菜单退出应用，包括托盘进程。
4. 运行安装脚本，将参数换成你实际的 DSH 可执行文件路径：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-desktop.ps1 -DesktopExe "C:\你的DSH安装目录\DeepSeek Harness.exe"
```

脚本构建并打包插件，使用 DSH 自带的 Node/pnpm 安装到 `%USERPROFILE%\.dsh\profiles\desktop`。如果自定义过 DSH Home，请额外传入 `-DshHome "你的DSH数据目录"`。打包文件存于项目内 `releases`，不包含小说工作数据。

5. 通过 DSH 原生插件管理确认 `dsh-moji` 已启用，不手工覆盖 profile。旧 `dsh-cuigengji` 安装需先备份作品与 profile，再通过宿主管理停用／移除旧插件本身，保留数据目录，然后安装新包。脚本发现旧依赖、bundle 或 patch 时会停止，不自动迁移插件身份。
6. 通过 DSH 自己的快捷方式重新启动，从左侧栏的“Moji”进入。

若找不到可执行文件，可查看桌面快捷方式的属性。不要用 CLI 创建或替换名为 `desktop` 的 profile；桌面 profile 由 DSH 桌面应用管理。

## 开始一起写

先创建或选择作品。你在当前会话选中的作品会成为 AI 的写作项目，可以直接告诉它：

> 先看看这本书的正文和相关设定，和我讨论下一章怎么推进，暂时不要续写。

> 把我们确定的走向更新到规划里，接在当前情节后面。

> 按这条规划续写下一章，保持人物动机和世界规则一致。

正文可直接编辑；规划支持多页、分组、拖拽连线和批注；设定支持角色卡、世界书、分组和关系图。写作预设在设置里，启用后作为该作品的写作要求提供给绑定会话。

## 作品保存在哪里

“工作数据 · 导入/导出”会显示实际保存位置。DSH 优先沿用已存在的旧默认 `cuigengji` 目录，不因品牌改名移动作品；没有旧目录时，新安装默认使用：

- Windows：`%LOCALAPPDATA%\moji`
- Linux/macOS：`$XDG_DATA_HOME/moji`；没有设置时使用 `~/.local/share/moji`

旧目录分别为同一父目录下的 `cuigengji`，仍兼容读取。升级前后应核对实际路径，不能仅按新名称推断作品已搬迁。

Windows 桌面版是当前主要验证环境；其他系统的默认目录已实现，但本次没有完成宿主适配验收。

如需修改位置，可在 desktop profile 的插件配置中设置 `dataRoot`，或使用 `MOJI_DATA_ROOT` 环境变量（旧 `CUIGENGJI_DATA_ROOT` 仍兼容）。优先级为插件配置、`MOJI_DATA_ROOT`、`CUIGENGJI_DATA_ROOT`、默认目录。配置不会自动搬运已有作品，请先导出备份，切换位置后在工作台导入。

不要把源码或插件安装目录作为小说目录。代码升级、Git 提交和 npm 打包都不应携带你的作品。

## 备份与迁移

- **作品与备份**：导出或恢复单本作品，包括正文历史、设定、规划和预设。
- **工作数据 · 导入/导出**：导出整个小说工作数据，导入前会展示预览和冲突，保存导入前快照。
- 同 ID、同内容会跳过；同 ID、不同内容不会直接覆盖。
- DSH 聊天记录、附件、账号配置和浏览器未保存草稿不属于小说备份。迁移 DSH 时需要另外处理。

升级前建议导出一份工作数据；不要用旧备份覆盖升级后新增的正文。详细存储边界见[架构说明](architecture.md)。

## 常见问题

**安装后没有入口**：检查 desktop profile 的 bundles 是否包含 `dsh-moji`，并完全退出、重启 DSH。脚本安装成功不代表正在运行的应用已经加载新插件。

**提示版本冲突**：保留草稿，读取最新内容后比较。不要修改版本号强行覆盖另一会话或 AI 的修改。

**找不到以前的作品**：检查“工作数据”显示的实际目录，再从旧环境导出备份。切换数据目录不会自动迁移。

**酒馆文件导入后效果不同**：我们保留资料和提示词内容，不运行酒馆的触发与装填规则；导入后检查和编辑内容，再启用预设。见[导入说明](tavern-import.md)和[预设说明](presets.md)。
