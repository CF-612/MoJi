# MoJi 分片存储与兼容边界

## 格式身份

MoJi 0.12.0 的存储改造借鉴上游的按实体拆分、当前值与历史分离，以及按操作读取；不把 MoJi 的统一剧情模型替换成上游规划模型。

- 新磁盘库：`format: "moji-library"`、`storageVersion: 5`。
- 继续读取并迁移旧 `cuigengji-library` v2/v3/v4，以及旧单文件工作库。
- 上游 `cuigengji-library` v5 **不是**本格式，仍拒绝原地打开；通过上游导出的可移植作品包导入。
- 作品包 `cuigengji-package` v1、工作库备份 `cuigengji-workspace` v1 的逻辑结构不变。物理目录、分片引用不会进入作品内容。
- 旧程序不认识新物理格式，必须失败关闭，不能降版本号后强行写入。

## 磁盘布局

章节、人物世界资料、旧规划的原有命名布局不变。`project.json` 不再携带完整 `story` / `writing`：

```text
novels/<作品目录>/
  project.json
  story/index.json
  story/fragments/<sha256>.json
  writing/index.json
  writing/fragments/<sha256>.json
```

索引带格式、版本和载荷校验和；每个片段以精确 JSON 字节的 SHA-256 命名，读取时验证。剧情当前卡片、页面、其余元数据分别保存。历史与重做记录保存独立描述，与当前记录共享未变化的不可变片段。结构资料按已有记录集合拆分，每条记录的当前值与 `versions` 分开。未知字段保留在原所属对象的元数据中；不重建 ID、不排序数组、不换算日期或小数。

保存只增加变化片段、更新索引，并在同一事务中删除旧索引确知且新索引不再引用的片段。不会扫描删除作者的额外文件。读取缓存返回克隆对象，当前值和历史不能因共享片段而共享可变对象。

## 实际按需读取范围

- `story.get`、`story.backup` 和 `story.apply` 读取当前剧情、正文目录元数据，以及引用保护所需的结构资料；不读取无关正文、旧规划页面或旧剧情快照正文。
- 快速路径先在克隆上校验当前剧情结构、版本、页面／轨道 ID 与层级；物理哈希不能代替业务校验。`story.apply` 新增／修改正文证据时，读取所引用章节的正文与版本历史。伪造或过期证据仍拒绝。
- 历史列表使用不暴露给外部的延迟快照视图。保存只允许原样复用其已校验描述，不能把只含版本号的预览当完整快照写回。目录自动同步即使发生在 `story.get`，也保全旧历史。
- 普通章节读取不加载剧情和结构资料。字段列表、关系类型列表、结构资料历史查询不再整本加载。
- 撤销、重做、恢复、完整导出和证据依赖复杂的写操作继续完整读取／验证；当前剧情 API 本身返回所有当前卡片，因此没有声称它只读取一张卡。

这些边界用实际文件读取／写入路径断言验证；不以未测量的速度倍数作为结果。

## 迁移、故障和回退

旧 v2/v3 先沿原有迁移到命名布局 v4，再进入 MoJi 分片迁移。分片阶段先重建并验证完整源工作库，对拆分后重组对象做深相等检查，检查目标文件冲突和可用磁盘空间，再创建持久检查点：

```text
backups/before-moji-fragments-<时间>-<UUID>/
  store.json       # 完整迁移前逻辑工作库
  library.json     # 原索引原始字节
  migration.json   # 源摘要、源/目标格式身份
```

检查点的文件和目录同步完成后，才发布 FileTransaction 暂存事务；库索引最后写入。暂存失败不会覆盖原库。提交途中中断由原事务日志继续完成，不重新迁移或丢失缓存请求身份。缺失／损坏片段、哈希异常或未知格式都停止相关读取／完整导出，不能悄悄变成空库。

宿主升级协调器仍额外保留原始目录备份，并比较迁移前后的完整逻辑摘要。需要回退时保留现场和检查点，在独立目录恢复迁移前 `store.json` 或经验证的原始目录备份；这是恢复源，不是把新库的版本号改回去。自动崩溃恢复是**完成已提交事务**，不是擅自回滚作者后续写作。

`check-project-names-migration.mjs` 的默认演练仍只操作隔离副本。它现在分别报告：未重分区记录的字节一致、完整逻辑对象相等、备份往返，而不再把改写的项目元数据描述为字节不变。

## 云端 D1 是独立适配器

D1 不经过磁盘 ProjectStore。大工作库的新编码为 `moji-workspace-fragments` v1；保留旧原始 JSON、gzip 和 `cuigengji-workspace-fragments` v1 的读取。小于既有 512 KB 阈值的工作库仍使用原始／压缩路径。

云端对剧情和结构资料使用不可变树片段，复用未变化实体和历史；已有 owner 隔离、哈希校验、CAS 批事务和回退快照不变。超出既有 D1 查询预算的宽树使用有界的较粗分片回退，避免为粒度而引入无法保存的大量 SQL 语句。

**D1 服务目前仍完整水合工作库。** 本次减少重写／重复存储，不声称实现了云端按接口懒加载，也没有改变表结构或访问真实 owner 数据。旧云快照和其片段继续可读；旧程序不应原地写入新的物理信封。回退二进制前需用备份／导出恢复到独立兼容库。
