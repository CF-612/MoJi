# 作品统一搜索（0.8.9）

进入作品后，顶部“搜索”或 Ctrl / ⌘ + K 打开统一搜索。一次查找正文、角色、世界资料、规划、事件、伏笔及写作要求；按类型筛选，展示命中字段、原文摘录和版本。名称和别名优先，同名卡片显示独立 ID；点结果打开原条目。写作要求打开所属预设，首版不自动定位其块或正文中的字符位置。

手机用完整页面，沿用浅色／夜间主题。输入时不请求，点击搜索或 Enter 后只发送一次查询；中文输入法组合期间不提前提交。搜索不保存、不覆盖草稿；跳转沿用原编辑器的本地草稿和版本检查，同页不同条目也能正确打开。退出搜索不改变当前页面。

只搜当前作品已保存内容，不搜索本地未保存草稿、章节／资料历史、原始导入文件、待确认整理建议或回收站。角色与世界包括别名、摘要、详述及未归档可选字段。默认搜索启用的写作要求；作者可展开范围说明，选择包含停用要求。AI 搜索始终只读取启用要求，不受模型传入的 includeInactiveRequirements 影响。

## AI 和作者界面共用只读接口

`workbench_query` 的 `action: writing.search`，参数：

```json
{"novelId":"作品ID","query":"银钥匙","kinds":["chapter","character","world","planning","event","foreshadow","requirements"],"limit":20,"maxChars":12000}
```

`kinds` 可省略或指定子集。返回 `items / counts / total / snapshot / nextOffset / hasMore`。每项含稳定 ID、记录版本、类型、名称、命中字段和有限原文摘录；原文不当作指令。需要更完整内容时按类型调用原来的 get 接口，不默认返回整本小说。名称、别名优先于摘要、字段值和正文；查询始终是转义后的字面文本，无模糊推断或任意正则。

后续页使用原查询、范围及返回的 `snapshot / nextOffset`。若作品在分页期间变化，拒绝混合不同快照，重新搜索。查询最多 160 字符，limit 为 1～50，maxChars 为 2,000～24,000；空词返回空列表，不列出全文。结果预算可能减少单页数量，继续使用实际 nextOffset。计数按条目而非出现次数。

不新增全文数据库、模型服务或后台索引，不增加存储格式。手动查找时按需读取现有工作数据，回滚只涉及程序。首版不检索关系边、关系变化历史或装饰便签，也不自动滚动到正文词句位置。现有引用、版本历史及容量限制继续有效。

模型查询／修改的 action 输入形状固定为文字，命令白名单仍由服务端分别校验。workbench_open.capabilities 返回当前 queryActions/editActions；未来新增业务动作不再因旧的枚举名单被聊天端拒绝。旧版枚举客户端需最后刷新一次才能获得此输入形状；不扩展登录权限，也不允许通过查询执行写入。
