# 图表与联动工作台

版本 `0.7.0-connected-charts`。正文始终是第一个导航入口；仪表盘、章节图、故事图与资料编辑共用同一份记录。

## 图表入口

- **仪表盘**：分章字数柱状图、累计正文字数曲线、写作目标进度环、伏笔状态环。柱形与曲线节点可打开原章节；分卷筛选和伏笔状态筛选可交互。统计仍只使用已保存正文，累计曲线按章节目录，不是每日写作量。
- **规划 → 章节叙述图**：按当前章节目录排列，横向对齐事件、已确认实际出场的人物、伏笔埋设／推进／实际回收／计划回收，以及相关规划。伏笔线连接埋设至实际或计划回收章；实际回收用实线，计划回收用虚线。点击标记直接打开原记录。“本章联动”展示该章所有项目。
- 伏笔台账是章节图下方的可展开编辑区；从图标或正文进入伏笔会直接定位同一记录，同时保留章节图，不再只有独立伏笔页面。原情节画布保留，可与章节图切换。
- **设定 → 故事发生图**：横向是明确的事件顺序，纵向是参与的角色、世界和明确关联的伏笔。资料轴横向滑动时固定在左侧，事件节点可打开编辑；点资料可回到资料卡。图表不推断日期长度，事件参与也不自动确认出场或伏笔回收。
- **时间线**提供同样的故事图和章节图，并保留事件编辑与关系变化。每段图表显示 20 个事件或章节；故事图每段最多 25 条参与资料，原数据保留。多项内容的章节可从联动资料入口查看完整记录。
- **正文**上方增加本章联动条，可打开事件、已确认人物和伏笔；正式出场仍从“本章资料”使用原文依据确认。

手机图表使用独立滚动区域，保持字体可读，页面本身不横向溢出；可横向滑动查看其他列。章节图的实际出场和伏笔依据仍会在正文改写后提示复核，不从名称匹配自动记录。

## 默认资料字段

新建角色卡直接显示姓名、可选性别说明、身份／职业、年龄、所属组织和别名。新建世界书显示名称、可选类别、所属区域／组织、适用时期和别名。类别提供地点、组织、物品、规则、种族、历史、其他建议，也允许自定义。

默认字段与自由详述、已有预设和自定义字段共存，空项不强制填写，旧资料不自动解析。已填性别／身份或世界类别显示为列表与画布标签，并可筛选。使用稳定字段 ID，不重复保存人物姓名。新建资料和字段一次提交，失败不留下半张卡片，重复相同请求不会再创建。

## 切页与更新

已读取的页面与图表保留在当前界面的内存缓存中，按会话、作品、对象和筛选隔离。切回时先显示内容，并标注“正在核对最新资料”，同时重新向服务端读取。字段、正文和事件的草稿继续保留原版本基线；保存仍检查当前版本，缓存不会绕过冲突保护。

写入及恢复会使旧请求失去缓存写入资格，避免保存前的慢请求覆盖新缓存。缓存有数量上限，不新增磁盘上的小说副本。退出／重新加载界面后重新读取，首次访问仍需要联网。缓存不会代替服务端鉴权，权限失败仍拒绝读写。

图表数据统一使用 `writing.board.get`：一次返回统计和章节／事件／人物／伏笔／规划的紧凑联动投影，不返回整本正文和历史。进入作品后延后预读这份投影，多个入口共用；相同未完成读取由现有 RPC 合并，仍保留并发上限与读取重试。后台未展示的规划、关系阶段读取减少。

## AI 接口

- `writing.board.get`：显式指定 `novelId`，返回只读图表投影，`includeDeleted:true` 可用于事件历史恢复入口。
- `writing.card.create`：`{novelId,name,type,summary?,content?,aliases?,groupId?,values?,requestId,connection?}`。`values` 使用既有字段 ID，如 `character:gender`、`character:occupation`、`world:category`。可选连接为 `{id,side,expectedRevision}`，新卡、字段和连接在同一次事务保存。
- 修改既有字段、事件、伏笔和章节继续使用原写入接口和读取版本，图表没有第二份台账。

## 验证与回退

备份与版本管理沿用既定流程：本地 Git bundle、稳定界面、云端 SQL 解码校验，公开源码不含作品、日志、备份或个人配置。提供旧稳定界面＋新版服务的备用回退；作品数据不随界面回退。

测试覆盖一次保存／失败回滚／重试去重、图表出场与事件参与分离、伏笔埋设与实际回收、正文复核、缓存隔离和旧请求保护，以及原有回归与本地 D1／Worker。内置浏览器使用虚构作品验证手机新建字段、图表到正文／伏笔跳转和 390px 布局；模拟每次读取延迟 1.2 秒时，已预读仪表盘与章节图仍立即显示，后台继续核对。

这不是断网编辑模式：未读内容仍需联网，保存失败仍保留草稿。没有性能追踪工具可用，因此不声称测得 INP／Lighthouse 分数。安卓实机键盘、触控与宿主布局需要作者验收后打发布标签。
