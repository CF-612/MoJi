# 本章整理建议（0.8.8）

正文工具栏 → 整理建议；本章资料也有可展开入口。统一预览本章的角色实际出场／提及、事件和伏笔新建／更新。默认不选任何候选，核对原文后选择采用；未选择项继续待确认，也可忽略。忽略只关闭候选，不删除正文或已有事实。手机使用全页，浅色和深色沿用设备设置。

无需新增模型 API、后台扫描或上传小说到额外服务。让当前聊天 AI 读取作者指定范围并提交建议即可。作者也可用姓名匹配建立一批候选：角色默认“仅被提及”，绝不自动判定出场；同名资料单独显示。

## 共用接口

`workbench_query` 的 `action: writing.review.preview`：

```json
{
  "novelId": "作品ID",
  "chapterId": "章节ID",
  "expectedChapterRevision": 3,
  "title": "第一章整理建议",
  "items": [
    {"id":"actor-1","kind":"link","nodeId":"角色ID","linkKind":"appearance","evidence":"已保存正文的原句","reason":"角色实际做了动作"},
    {"id":"event-1","kind":"event","evidence":"已保存正文的原句","value":{"title":"收到来信","storyTime":"雨夜","order":10,"narrativeKind":"linear","memoryRefs":["角色ID"]}},
    {"id":"shadow-1","kind":"foreshadow","value":{"title":"信封上的印记","status":"planted","memoryRefs":["角色ID"],"evidence":[{"kind":"plant","chapterId":"章节ID","revision":3,"evidence":"已保存正文的原句"}]}}
  ]
}
```

预览不写入，返回 `proof`。以完全相同输入加上 `proof` 和稳定 `requestId`，通过 `workbench_edit` 的 `writing.review.submit` 保留候选。提交通知不是事实确认，不得声称已整理进正式时间线或出场索引。

`writing.review.list` 可带 `chapterId`；`writing.review.get` 用 `id` 返回逐项内容、处理状态和失效标记。作者选择后 `writing.review.apply` 用 `id / expectedRevision / itemIds / confirmed:true / requestId` 原子采用。仅当作者明确授权采用时 AI 才能调用。`writing.review.dismiss` 参数相同，关闭所选候选。更新已有伏笔的候选另带 `targetId / expectedRevision`，`value` 可只包含要更新的字段；预览会显示合并后的完整内容。

每批 1～30 项，最多 100,000 字符。建议限于一个已保存章节；事件强制引用该章节及其原文。未指定事件顺序时按本批顺序追加，日期不推断。事件关联人物不证明实际出场。伏笔需本章证据，正式回收仍需要埋设和回收依据。跨章批量分析、资料字段提取、关系变化候选和候选内相互引用留后续。

## 伏笔进度约定

伏笔仍可处于计划、已埋设、推进中或部分回收；尚在创作中的线索不得自动判为放弃。最终结果只有已完成（`recovered`）或已放弃（`abandoned`）。节点模式的 `resolution` 仅接受 `active / complete / abandoned`；放弃必须附 `abandonReason`，完成仍需已确认的埋设与回收正文依据。不得再提交 `status: open` 或 `resolution: open`。

旧备份中的开放结局以只读兼容视图归为已放弃，显示明确的旧版转换说明；不会为读取或导入而改写原记录、正文依据、节点或版本历史。首次编辑时保存新状态，并把原始记录留在历史中。此兼容只适用于已有记录和备份，不允许新建开放结局。

## 版本与数据保护

可选 `writing.reviews` 与原有正文、事件、关联、伏笔分开保存。记录稳定 ID、版本、来源、原文版本、逐项处理状态及处理人。所有事实写入复用原业务接口与历史，不复制独立台账。

预览指纹覆盖候选内容及相关记录版本。采用前检查整批选择的章节、资料、关联规划及伏笔版本；新增事件的排序也检查已有事件集合。失败时保留整批候选。正文改写或资料改动后不自动迁移依据，需重新整理。无关资料修改不应导致所有建议失效。确认和忽略均需稳定请求标识；丢失响应后重试不重复写入。

完整 JSON / 云端备份保留待确认与已处理候选；作品复制重映射章节、资料、规划、伏笔及结果引用。部分导出不包含超出所选范围的候选，并计入省略数。旧作品无需预填新结构。第一次保存候选将该作品的 writing 扩展标记为版本 2，新版兼容版本 1 和 2；旧版的结构操作与备份导入会拒绝版本 2。回退时使用兼容业务层，只退界面，不回退正文数据。

验收包括只读预览、提交后无事实写入、部分采用、同名及提及区别、丢失响应重试、过期版本、错误证据、批内冲突原子性、已有伏笔更新与历史、复制与部分导出、真实本地 D1 双端处理。界面用虚构资料测试，不改真实小说。
