# 直接编辑时间线（0.9.1）

竖向时间线的事件条提供 ⠿ 移动手柄，以及首尾短线。电脑也可直接拖动事件条正文区域；手机正常滑动仍用于浏览，只有手柄开始位置编辑。点击手柄或用键盘激活，可通过章节选择框操作，不依赖精确拖动。

拖动过程只显示预览，松手后显示范围、增加和移出的章节关联。点击“保存位置”才写作品。关闭窗口仍保留本设备、当前作品的位置草稿，顶部可继续调整或明确丢弃；重新打开工作台也能恢复该草稿。一次保留一份位置草稿，另一次调整替换前会询问。

章节顺序支持整体移动和首尾调整。整体移动保留跨度及未关联的间隔；首尾扩展增加覆盖的新章节，缩短至原间隔内时，将新边界章明确加入关联。也可在选择框中明确指定连续范围。仍在范围内的原章节引用、原版本和原文依据保留。新关联使用该章当前读取版本并留空原文依据；移出的旧引用保留在事件历史里。已删除章节的历史引用不因可见范围调整而丢失。最多 200 条章节引用。

故事时间视图只移动事件顺序，不通过拉伸事件条伪造日期区间。调整故事先后会重算阶段关系，并冻结旧的叙述排序，日期和正文章节位置保持。两条轴仍只能切换。

位置操作不复制或移动正文、角色正式出场记录、伏笔正文依据或章节规划。事件关联的规划、人物与伏笔仍依靠同一个事件 ID 联动。

保存检查事件版本；章节位置还检查完整当前章节 ID 顺序及原引用和目标章的当前版本。故事顺序检查完整事件顺序与版本。冲突保留目标位置，作者需点击“保留目标位置并核对最新版本”，再决定保存，不自动改换依据或重试写入。无关章节纯正文改写不会使位置操作全部失效。重复请求通过稳定 requestId 去重；历史恢复继续使用原事件恢复入口。

## AI 共用操作

`workbench_edit` 的 `writing.event.place`，通用参数 `novelId/id/expectedRevision/view/operation/confirmed:true/requestId`。

- `view: narration`：`operation` 为 `move`、`resize-start`、`resize-end` 或 `range`；提供 `startChapterId/endChapterId`、`expectedChapterOrder`（完整活动章节 ID 顺序）和 `chapterRevisions`（原引用及目标章当前版本映射）。`move` 维持跨度及原间隔；`range` 明确指定连续范围。
- `view: story`：仅 `operation: move`；提供 `beforeEventId`（放在此事件之前，null 表示末尾）和 `expectedOrder`（完整当前故事顺序的 `{id,revision}` 数组）。

分别从 `writing.board.get` 与 `writing.event.get` 读取快照。返回实际变更事件及 changed 标记；新增章节关联无正文依据，不得声称已确认这些章节中的出场或伏笔事实。接口不新增登录权限、模型服务或作品数据格式。

本批只完成直接位置编辑。AI 跨章统一候选与关系变化候选仍为后续工作。
