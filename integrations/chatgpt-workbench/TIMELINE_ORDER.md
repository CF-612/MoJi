# 时间节点排序 0.8.5

竖向时间线仍只显示一个轴，顶部切换“章节顺序／故事时间”。选择事件后，就地使用上移／下移；上方“上一个／下一个时间节点”只切换查看位置，不写入。

- 故事轴调整故事先后，重新投影进入资料和关系阶段；不改已填日期或出生日期，不自动把计划认定为正文事实。
- 章节轴只调整当前章的事件排列，章节本身不移动，正文不修改。跨章位置仍通过事件编辑中的章节关联处理。
- 同一事件呈现在多章时，各章排序分别保存；未关联有效正文的事件在待写区单独排序。
- 两轴独立：第一次调整故事先后时，固定原有章节内及待写顺序，避免旧数据借用故事排序而一同变化。数值只表示明确先后，不表示真实时间间隔。
- 保存回执立即更新已读取的时间线，保持选中事件，不等页面重新载入。保存失败不移动；读取最新后由作者重新操作。请求去重防止一次操作重试移动两次。

## 共用 AI 接口

`workbench_edit` 的 `writing.event.move` 支持：

| 参数 | 含义 |
| --- | --- |
| novelId、id | 作品及选中的事件 |
| view | story 或 narration |
| direction | up 或 down |
| chapterId、expectedChapterRevision | narration 的当前章；chapterId 留空只排序未关联正文的事件 |
| expectedOrder | 按当前范围的已有顺序传入全部 `{id,revision}`；从 writing.board.get 的事件投影读取 |
| confirmed、requestId、reason | 作者明确要求调整后传 confirmed:true、稳定请求 ID 及原因 |

新增、删除、修改或改序导致范围与读取结果不同，整个操作拒绝写入。返回 order（新 ID 顺序）及 events（本次更新的事件，不含历史全文）。不改事件与规划、伏笔、人物、正文的引用 ID。

## 数据与回退

新增可选 `chapterOrders` 映射，用章节 ID 保存本章排列；旧备份缺少该字段时沿用原顺序。移除章节呈现时清除对应当前排序，旧值仍在事件历史中。完整备份／复制包含当前和历史映射，复制时重映射章节 ID；范围导出继续检查全部历史引用。

代码回退使用当前业务层配上一稳定界面的兼容构建，不退回无法识别 chapterOrders 的旧业务层，不恢复或覆盖最新作品。部署前保留源码 bundle、上一稳定 HTML 及本地云端 SQL 备份。
